# JS2Go Agent Testability Experiment

[Спецификация](spec.md) и [фиксированный бриф CALC-01](briefs/calc-01.md).

## Контрольный прогон R0

Запускайте из корня репозитория с Node.js 22 и npm 10.

```sh
npm ci
npx playwright install chromium
npm run agent:reference
```

Команда `agent:reference` проверяет SHA исходного коммита и SHA-256 fixture из `configs/baseline.json`. Она извлекает исходники коммита во временный каталог через `git archive` и запускает локальный Next.js через `next dev` с Webpack. Turbopack не поддерживает ссылку на общие зависимости из этой копии. Временный каталог исключает локальные `.env` и базы данных.

Каждый запуск применяет штатные миграции к новой SQLite, создаёт одного тестового пользователя и начинает с пустой коллекции проектов и нового контекста Chromium. Тестовая авторизация задаётся через `storageState`. Браузер ходит к локальному JS2Go, берёт точную версию Monaco из установленных зависимостей и блокирует остальные сетевые запросы. Preview на `srcDoc` разделяет origin с редактором, как в исходном JS2Go. Тестовое окружение содержит только одноразовую сессию и фиктивный ключ локального upstream.

Контрольный тест проходит C1–C8 через UI. Он проверяет новый URL проекта, завершённый SSE и HTML в истории, изменение текста Monaco после Patch и оба результата в конкретном элементе внутри preview. В `artifacts/` сохраняются отчет Playwright, trace, снимки DOM и ARIA, ответ `/api/ai`, лог Next.js и `run.json` с версиями инструментов и хешем окружения. Все эти данные исключены из Git.

## Запись ответа

Укажите выделенный тестовый ключ DeepSeek в `JS2GO_RECORD_DEEPSEEK_KEY` и запустите:

```sh
npm run agent:reference -- --capture
```

Ключ использует только локальный прокси и только для запроса к `api.deepseek.com`. JS2Go отправляет запрос с фиктивным ключом на локальный адрес через штатный `AI_BASE_URL_DEEPSEEK`. Завершённый ответ сохраняется как `capture.json.gz` в каталоге прогона. В него входят порции upstream SSE с относительными временными метками и полный SSE, полученный браузером от `/api/ai`. Повторный запуск воспроизводит поток на границе провайдера и сравнивает полученный в браузере SSE с fixture.

`fixtures/R0.json.gz` содержит реальный ответ DeepSeek от 25 ноября 2026 года. Запрос использовал `deepseek-chat`, провайдер указал `deepseek-flash` в потоке. Записано 1103 порции за 14,9 секунды. Первый прогон capture остановился на C6 из-за локатора, который прочитал историю вместе с результатом. Проверочный replay использует ту же запись и точный локатор поля результата.

## Контрольный прогон и подготовка R1

[Fixture R1](fixtures/R1.json.gz) получен из записи R0. [Diff калькулятора](fixtures/R0-to-R1.patch) показывает HTML IDs и обновлённый JS-селектор результата. График из 1103 временных меток upstream SSE сохранён. SHA-256 fixture записан в [конфигурации R1](configs/R1.json).

[Приватный тест R1](reference-r1/calc-01.spec.ts) проходит C1–C8 через новые IDs, начинает сценарий с главной страницы и проверяет уникальность IDs в снимках. До коммита для контрольного прогона исходники извлечены через `git archive` из дерева, собранного во временном Git index. `sourceTree` фиксирует проверенное дерево `src`. В каталоге `artifacts/reference-R1-*` сохраняются `run.json`, фактический SSE, отчёт Playwright, trace и DOM/ARIA-снимки.

После утверждения продуктового коммита сверьте `git rev-parse <commit>:src` с `sourceTree` и запишите SHA коммита в `sourceSha` в `configs/R1.json`. Подготовьте отдельное рабочее дерево из корня репозитория.

```sh
node experiments/agent-testability/stage-revision.mjs experiments/agent-testability/configs/R1.json
```

В подготовленном рабочем дереве конфигурация R1 используется как `baseline.json`. Запускайте benchmark оттуда после согласования бюджета.

## Benchmark R0

Smoke запускает одну отдельную сессию Codex. На macOS ARM64 необходимы Node.js, npm, Codex CLI и Chromium из `configs/experiment.json`, а также действующий вход в Codex через ChatGPT. Для отдельной учётной записи можно указать путь к файлу авторизации через `JS2GO_CODEX_AUTH`.

```sh
npm run agent:smoke -- --revision R0
npm run agent:report
```

Агент получает фиксированный бриф, URL, шаблон Playwright и две команды. `./browser` исследует UI через снимки доступности, чтение DOM и действия по локаторам. `./run-test` сохраняет неизменяемую копию `calc.spec.ts` перед запуском. Codex работает в отдельном workspace с закрытым сетевым доступом. Браузер и процесс Playwright используют ограниченные файловые права и локальные подключения. Временная авторизация JS2Go добавляется прокси на стороне сервера. Прокси ограничивает доступ к ресурсам отладки Next.js, а dev-сборка для benchmark отключает карты исходников. Перед запуском Codex runner проверяет блокировку чтения приватного файла, исходников и fixture, прямого доступа к JS2Go и чтения приватного файла браузером.

Для исследования, каждого запуска, каждого независимого replay и мутаций runner создаёт отдельную SQLite и контекст Chromium. Первые и финальные байты теста проверяются в независимых прогонах. Кандидат может задать положительный таймаут в пределах лимита Playwright из конфигурации. Два отрицательных контроля меняют по одному оператору в копии потока fixture в памяти. Runner сохраняет записи всех запусков, включая ошибки сбора теста и отказы инфраструктуры.

Каталог прогона содержит `run.json`, `codex.jsonl`, сопоставленный сессии `codex.rollout.jsonl` при наличии, `tool-events.jsonl`, `.candidates/`, Playwright JSON и traces, `grade.json` и `metrics.json`. Для валидного replay заполните приватный `review.json` по форме `review.required.json`. Для каждого C1–C8 укажите `status` как `passed` или `failed` и приведите `evidence` из кандидата и replay. Статус `unverified` исключает strict pass. Один и тот же SHA допускает общую оценку семантики при независимом replay обеих ролей.

```sh
npm run agent:grade -- <каталог-прогона>
npm run agent:report
```

Токены берутся из завершённого события Codex, а наблюдаемые ответы модели считаются по уникальным `response_id` в сопоставленном rollout. При наличии обоих источников суммы сверяются. `null` означает отсутствие подтверждённого наблюдения. Время генерации в `metrics.json` измеряется на локальной границе recorded upstream финального replay. Отчёт сохраняет `summary.json`, `comparison.csv` и `report.md` в `artifacts/`. Он группирует прогоны по конфигурации и показывает smoke, pilot и main отдельно.

Для pilot или main нужно согласовать бюджет. После согласования установите `JS2GO_APPROVED_RUN` в формате `R0/<фаза>/<число-попыток>` и передайте те же значения в `npm run agent:benchmark -- --revision R0 --phase <фаза> --trials <число-попыток> --mode recorded`.

## Действия пользователя и автотеста

`npm run agent:report` добавляет в отчёт сравнение с 17 шагами CALC-01 от открытой главной страницы. Семь шагов открывают калькулятор, пять проверяют сложение, один очищает результат, четыре проверяют умножение. Ввод prompt считается одним шагом. Начальная навигация измеряется отдельно.

Автоматический подсчёт использует завершённые вызовы ввода из независимого replay финального теста. Отношение `1,00` соответствует длине эталонного пути при покрытии C1–C8. В отчёте также указаны действия Codex при исследовании, число запусков теста и число проверенных хешей. Подробности и пути к трассам находятся в `artifacts/actions.json`.

## Сравнение браузерных инструментов A и B

A0–A2 — уже измеренная контрольная группа. B0–B2 используют те же продуктовые коммиты, записи SSE, пользовательский бриф и версии инструментов. Подготовка отдельного рабочего дерева сначала сверяет хеши A, затем устанавливает браузерные команды и инструкции B.

```sh
node experiments/agent-testability/stage-revision.mjs experiments/agent-testability/configs/R2.json --interface B
npm run agent:report:interface
```

Первую команду запускайте из корня репозитория. Она выводит путь временного дерева для `agent:smoke` или согласованной серии `agent:benchmark`. Для B0 используйте `configs/baseline.json`, для B1 — `configs/R1.json`. Отчёт собирается из корня основного репозитория и охватывает обе группы.

В B доступны локаторы Playwright по роли и точному доступному имени, именованная область снимка, ожидание текста или атрибута и ограниченное чтение. В компактных снимках длинные блоки кода заменяются отметкой об их размере. Инструкция запуска теста удерживает ожидание процесса внутри одного вызова инструмента. [Локаторы Playwright](https://playwright.dev/docs/locators) · [Ожидания Playwright](https://playwright.dev/docs/test-assertions)

`artifacts/interface-report.md` показывает входные токены, максимальный наблюдаемый вход, объём снимков в байтах, явные ожидания состояния, отдельные обращения к модели за состоянием процесса, время теста и долю семантических локаторов. Повторы снимка между действиями выделены отдельно. `artifacts/interface-summary.json` содержит данные по каждому прогону.

## Измеренные результаты CALC-01

Каждая ревизия A включает пять сессий Codex, каждая ревизия B — одну. Число LLM-ответов и входных токенов для A приведено по медиане. Первый проход в таблице означает строгую проверку среди сессий, дошедших до Codex.

| Ревизия | Первый проход A → B | LLM-ответы A → B | Входные токены A → B | Отдельные опросы процесса A → B |
|---|---:|---:|---:|---:|
| R0 | 4/5 → 1/1 | 29 → 23 | 634 539 → 434 033 | 4 → 0 |
| R1 | 5/5 → 1/1 | 27 → 23 | 611 614 → 440 008 | 3 → 0 |
| R2 | 5/5 → 0/1 | 30 → 22 | 717 336 → 407 840 | 4 → 0 |

Пять инфраструктурных отказов A1 произошли до запуска Codex, поэтому по всем запускам строгий результат A1 составляет 5/10. Все три кандидата B прошли независимый replay и обнаружили обе мутации. B2 отклонён строгой проверкой из-за таймаута теста 150 секунд при лимите 120 секунд. Эти результаты описывают один сценарий с записанным ответом генератора. Полные журналы и трассы сохраняются локально в `artifacts/`.
